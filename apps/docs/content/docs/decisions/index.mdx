Architecture Decision Records. Each one has the same four parts: the
**context** the decision was made in, the **decision**, the **consequences**
we accepted, and **when to revisit** — the conditions under which the other
option would win. A decision without the last part is a preference.

Statuses: *Accepted* means the code does this today. *Accepted, not yet
implemented* means the decision stands and the roadmap carries the work.

## Writing a new one

Copy the newest file, bump the number, keep the four parts. An ADR is written
when the decision is made, not after — the value is in the context, which is
forgotten first.
